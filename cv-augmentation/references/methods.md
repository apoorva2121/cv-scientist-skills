# Augmentation: method inventory

Verified method inventory for the Computer Vision Scientist skill, area 2. It covers classification, multi-label, detection (including small and rotated objects), segmentation, pose/keypoints, depth, video, OCR/documents, medical 2D/3D, pathology, remote sensing/multispectral, thermal and, at reference level, point clouds. Decoding and file-integrity checks live in R1 section A1; this file starts where a decoded array exists.

**Checked 2026-09-27.** Versions and dates come from the PyPI JSON API (upload time of the first file of the latest release). Licence, archive status and last push come from the GitHub REST API, cross-checked with PyPI metadata. Papers were checked through the arXiv API (ID, title, first-version date); claims come from the abstract unless a section or table is named. Recipes were read from the official config files or argparse defaults on each repo's default branch on 2026-09-27. Normalisation constants come from Hugging Face `preprocessor_config.json` files and the DINOv3 README.

**"Maintained?" legend** (relative to 2026-09-27): **Active** = release or push within 6 months; **Slow** = newest release/push 6-18 months old; **Stale** = nothing for more than 18 months; **Archived** = GitHub repo is read-only; **Method** = a paper or technique, not a package.

**Licence policy note.** Two widely used augmentation code bases are now copyleft: **AlbumentationsX** (AGPL-3.0-only or commercial) and **Ultralytics** (AGPL-3.0). Under a permissive-only policy (MIT/BSD/Apache), use `torchvision.transforms.v2`, Kornia, timm, MONAI, TorchIO or the pinned, archived MIT `albumentations==2.0.8`, and take Mosaic/MixUp/copy-paste from permissive implementations (Kornia `RandomMosaic`/`RandomMixUpV2`/`RandomTransplantation`, legacy Albumentations `Mosaic`, torchvision `MixUp`/`CutMix`) or from the papers, rather than copying Ultralytics code.

**What changed recently (verified 2026-09-27)**
- The MIT `albumentations` repo was **archived on 2025-07-10** (last release 2.0.8, 2025-05-27). Development moved to `albumentationsx`, which is **AGPL-3.0-only or commercial**, collects telemetry by default and installs under the same import name (A1).
- `torchvision.transforms.v2` now handles rotated boxes and (beta) keypoints (0.23+); `torchvision.io` video was removed in 0.26 and its image decoders are deprecated in 0.29 in favour of TorchCodec (A1, A2).
- `imgaug` (last release 2020) breaks on NumPy >= 1.24 and NumPy 2; `StainTools` is archived (A1, A3).
- Normalisation is checkpoint-specific: SigLIP/SigLIP 2 use 0.5/0.5, CLIP and AIMv2 use OpenAI CLIP stats, DINOv3 satellite weights use their own stats (B3).
- ImageNet-C corruptions are no longer out-of-distribution for web-scale models (LAION-C, ICML 2025), and a 2026 study found standard TTA hurt accuracy on 11 of 12 medical model-dataset pairs (C8, C9).
- Current real-time DETR recipes (DEIM, DEIMv2) schedule Mosaic/MixUp/CopyBlend **on** after a warm-up and **off** for the last 8 epochs (C5, D).
- **DEIMv2 was relicensed on 2026-08-24 from Apache-2.0 to a custom non-commercial licence** covering code and weights. Under a permissive policy use DEIM, D-FINE, RT-DETR (all Apache-2.0) or RF-DETR (Apache-2.0) recipes instead (D). The DeiT, ConvNeXt and Mask2Former repos are archived; their configs still document the recipes.

## Decision guidance with citations

**Universal order of work.** (1) Fix decoding (EXIF, ICC, mode, bit depth; R1 A1). (2) Copy the pretrained checkpoint's own preprocessing exactly: resize, interpolation, crop, mean/std (B3; `resolve_model_data_config`, `AutoImageProcessor`). (3) Start from the model family's published recipe (D), then change **one** augmentation at a time and measure against a seed-to-seed noise floor on a fixed validation set. (4) Evaluate on untouched real data that reflects deployment conditions; keep synthetic and TTA out of the yardstick until each has been validated.

**Library choice under a permissive-licence policy.** torchvision v2 (boxes, rotated boxes, masks, keypoints, video) + Kornia for GPU + timm for classification policies + MONAI/TorchIO for medical + TorchGeo for remote sensing. Keep `albumentations==2.0.8` (MIT, archived) only for existing pipelines. Do not add `albumentationsx` or copy Ultralytics augmentation code unless the project accepts AGPL or buys a licence (A1, A3). Do not start new work on imgaug (breaks on NumPy >= 1.24) or StainTools (archived). DEIMv2 code and weights are non-commercial since 2026-08-24; its augmentation ideas (Mosaic + MixUp + CopyBlend schedule) can be re-implemented from the paper.

| Task / data type | Try first | Then consider | Avoid |
|---|---|---|---|

AugReg: transfer beats scratch; heavy AugReg hurts short runs (arXiv 2106.10270) | FixRes-style higher test resolution or short fine-tune at test size (arXiv 1906.06423); per-class accuracy check (arXiv 2401.01764) | DeiT-strength augmentation for a 10-epoch fine-tune; colour jitter when colour is the label |
| Classification from scratch (>= ImageNet-1k scale) | DeiT III 3-Augment + Mixup/CutMix + BCE, or DeiT/ConvNeXt RandAugment recipe; RSB A1-A3 for ResNets (D) | TransMix/other mixes for ViTs (small gains) | Random erasing on top of 3-Augment (DeiT III removed it) |
| Multi-label | RRC with a high minimum scale, flips, colour jitter; Mixup with union/soft labels | TrivialAugment | CutMix and aggressive crops that remove labelled objects without updating the labels |
| Detection (general) | The detector's own recipe: Ultralytics defaults, or RT-DETRv2/D-FINE/DEIM ops (photometric distort, zoom-out, IoU crop, flip, multi-scale); switch Mosaic/strong ops off for the last ~8-15 epochs (YOLOX arXiv 2107.08430; D) | Copy-Paste for rare classes (arXiv 2012.07177); DEIMv2 CopyBlend; weaker Mosaic for small models (YOLOX) | Mosaic until the last epoch; rotating axis-aligned boxes by large angles |
