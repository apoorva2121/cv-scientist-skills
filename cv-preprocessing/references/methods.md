# Preprocessing: method inventory

Verified method inventory for the Computer Vision Scientist skill, area 2. It covers classification, multi-label, detection (including small and rotated objects), segmentation, pose/keypoints, depth, video, OCR/documents, medical 2D/3D, pathology, remote sensing/multispectral, thermal and, at reference level, point clouds. Decoding and file-integrity checks live in R1 section A1; this file starts where a decoded array exists.

**Checked 2026-09-27.** Versions and dates come from the PyPI JSON API (upload time of the first file of the latest release). Licence, archive status and last push come from the GitHub REST API, cross-checked with PyPI metadata. Papers were checked through the arXiv API (ID, title, first-version date); claims come from the abstract unless a section or table is named. Recipes were read from the official config files or argparse defaults on each repo's default branch on 2026-09-27. Normalisation constants come from Hugging Face `preprocessor_config.json` files and the DINOv3 README.

**"Maintained?" legend** (relative to 2026-09-27): **Active** = release or push within 6 months; **Slow** = newest release/push 6-18 months old; **Stale** = nothing for more than 18 months; **Archived** = GitHub repo is read-only; **Method** = a paper or technique, not a package.

**Licence policy note.** Two widely used augmentation code bases are now copyleft: **AlbumentationsX** (AGPL-3.0-only or commercial) and **Ultralytics** (AGPL-3.0). Under a permissive-only policy (MIT/BSD/Apache), use `torchvision.transforms.v2`, Kornia, timm, MONAI, TorchIO or the pinned, archived MIT `albumentations==2.0.8`, and take Mosaic/MixUp/copy-paste from permissive implementations (Kornia `RandomMosaic`/`RandomMixUpV2`/`RandomTransplantation`, legacy Albumentations `Mosaic`, torchvision `MixUp`/`CutMix`) or from the papers, rather than copying Ultralytics code.

**What changed recently (verified 2026-09-27)**
- The MIT `albumentations` repo was **archived on 2025-07-10** (last release 2.0.8, 2025-05-27). Development moved to `albumentationsx`, which is **AGPL-3.0-only or commercial**, collects telemetry by default and installs under the same import name (A1).
- `torchvision.transforms.v2` now handles rotated boxes and (beta) keypoints (0.23+); `torchvision.io` video was removed in 0.26 and its image decoders are deprecated in 0.29 in favour of TorchCodec (A1, A2).
- `imgaug` (last release 2020) breaks on NumPy >= 1.24 and NumPy 2; `StainTools` is archived (A1, A3).
- Normalisation is checkpoint-specific: SigLIP/SigLIP 2 use 0.5/0.5, CLIP and AIMv2 use OpenAI CLIP stats, DINOv3 satellite weights use their own stats (B3).
- ImageNet-C corruptions are no longer out-of-distribution for web-scale models (LAION-C, ICML 2025), and a 2026 study found standard TTA hurt accuracy on 11 of 12 medical model-dataset pairs (C8, C9).
- Current real-time DETR recipes (DEIM, DEIMv2) schedule Mosaic/MixUp/CopyBlend **on** after a warm-up and **off** for the last 8 epochs (C5, D).
- **DEIMv2 was relicensed on 2026-08-24 from Apache-2.0 to a custom non-commercial licence** covering code and weights. Under a permissive policy use DEIM, D-FINE, RT-DETR (all Apache-2.0) or RF-DETR (Apache-2.0) recipes instead (D). The DeiT, ConvNeXt and Mask2Former repos are archived; their configs still document the recipes.

## B. Preprocessing

Rule for everything in this section: **the serving path must run the same code, library, interpolation, antialias flag, colour conversion and normalisation as the evaluation path.** Save the preprocessing config with the model and test train/serve parity with a pixel-diff unit test.

**Evidence on whether enhancement helps downstream accuracy**

| Finding | Task / data | Source |
|---|---|---|
| Dehazing methods "cannot improve much the image-classification performance and sometimes even reduce" it | Classification on synthetic and real haze | Pei et al., arXiv 1810.05716 |
| Existing restoration methods "cannot improve object detector performance and sometimes even reduce detection performance"; addressed by training restoration on detection-aware pseudo ground truth (a targeted adversarial attack) | Detection after dehazing / low-light enhancement | Sun et al., NeurIPS 2022, https://proceedings.neurips.cc/paper_files/paper/2022/hash/1cac8326ce3fbe79171db9754211530c-Abstract-Conference.html |
| RESIDE evaluates dehazers with a task-driven (detection) criterion alongside PSNR/SSIM, no-reference and subjective criteria | Dehazing benchmark | Li et al., arXiv 1712.04143 |
| SR helps other vision tasks **when inputs are low resolution**; perceptual metrics are not reliable proxies for usefulness | Edge detection, segmentation, digit and scene recognition | Dai et al., arXiv 1509.07009 |
| Super-resolving 30 cm satellite imagery to 15 cm gave a 13-36% mAP improvement; less benefit at coarser resolutions | Vehicle/plane/boat detection | Shermeyer and Van Etten, arXiv 1812.04098 |
| Cascading a denoiser with a high-level network and updating the denoiser with the joint (task) loss lets it "overcome the performance degradation" of high-level tasks on noisy input | Classification, segmentation under noise | Liu et al., arXiv 1706.04284 |
| Fine-tuning on noisy/blurred images "can alleviate much effect due to distorted inputs" | Classification under blur/noise | Zhou et al., arXiv 1701.01924 |
| Training on one distortion does not transfer to another (salt-and-pepper vs uniform noise) | Classification | Geirhos et al., arXiv 1808.08750 |
| Low-light survey evaluates enhancers by face detection in the dark as well as by image quality | LLIE methods on DARK FACE | Li et al., arXiv 2104.10729 |

## Decision guidance with citations

**Universal order of work.** (1) Fix decoding (EXIF, ICC, mode, bit depth; R1 A1). (2) Copy the pretrained checkpoint's own preprocessing exactly: resize, interpolation, crop, mean/std (B3; `resolve_model_data_config`, `AutoImageProcessor`). (3) Start from the model family's published recipe (D), then change **one** augmentation at a time and measure against a seed-to-seed noise floor on a fixed validation set. (4) Evaluate on untouched real data that reflects deployment conditions; keep synthetic and TTA out of the yardstick until each has been validated.

**Library choice under a permissive-licence policy.** torchvision v2 (boxes, rotated boxes, masks, keypoints, video) + Kornia for GPU + timm for classification policies + MONAI/TorchIO for medical + TorchGeo for remote sensing. Keep `albumentations==2.0.8` (MIT, archived) only for existing pipelines. Do not add `albumentationsx` or copy Ultralytics augmentation code unless the project accepts AGPL or buys a licence (A1, A3). Do not start new work on imgaug (breaks on NumPy >= 1.24) or StainTools (archived). DEIMv2 code and weights are non-commercial since 2026-08-24; its augmentation ideas (Mosaic + MixUp + CopyBlend schedule) can be re-implemented from the paper.

| Task / data type | Try first | Then consider | Avoid |
|---|---|---|---|
| Classification, fine-tuning a pretrained backbone | Checkpoint preprocessing; RRC (raise min scale for small objects) + flip; `TrivialAugmentWide` or `rand-m9-mstd0.5-inc1`; light Mixup/CutMix only for long schedules. AugReg: transfer beats scratch; heavy AugReg hurts short runs (arXiv 2106.10270) | FixRes-style higher test resolution or short fine-tune at test size (arXiv 1906.06423); per-class accuracy check (arXiv 2401.01764) | DeiT-strength augmentation for a 10-epoch fine-tune; colour jitter when colour is the label |
| Classification from scratch (>= ImageNet-1k scale) | DeiT III 3-Augment + Mixup/CutMix + BCE, or DeiT/ConvNeXt RandAugment recipe; RSB A1-A3 for ResNets (D) | TransMix/other mixes for ViTs (small gains) | Random erasing on top of 3-Augment (DeiT III removed it) |
| Multi-label | RRC with a high minimum scale, flips, colour jitter; Mixup with union/soft labels | TrivialAugment | CutMix and aggressive crops that remove labelled objects without updating the labels |
| Detection (general) | The detector's own recipe: Ultralytics defaults, or RT-DETRv2/D-FINE/DEIM ops (photometric distort, zoom-out, IoU crop, flip, multi-scale); switch Mosaic/strong ops off for the last ~8-15 epochs (YOLOX arXiv 2107.08430; D) | Copy-Paste for rare classes (arXiv 2012.07177); DEIMv2 CopyBlend; weaker Mosaic for small models (YOLOX) | Mosaic until the last epoch; rotating axis-aligned boxes by large angles |
| Small objects / high-resolution | Tile training images and infer with SAHI/`InferenceSlicer` at the same scale (arXiv 2202.06934); oversample + copy-paste small objects (arXiv 1902.07296) | SR only for genuinely low-resolution imagery (arXiv 1812.04098) | Downscaling a 4000-px image to 640 px and hoping |
| Rotated objects | OBB-native pipeline (torchvision v2 rotated formats; Ultralytics OBB; AlbumentationsX OBB if AGPL is acceptable); D4 for nadir imagery | Random rotations with OBB | Axis-aligned boxes for elongated rotated objects; mixing angle conventions |
| Semantic / instance / panoptic segmentation | Mask2Former-style: LSJ + crop (COCO), multi-scale + 512 crop + SSD colour aug + flip (ADE20K) (D); nearest-neighbour masks, ignore-index padding | Copy-Paste (instance), class-balanced crops (`RandCropByLabelClasses`, `SINGLE_CATEGORY_MAX_AREA`) | Bilinear interpolation of label maps |
| Pose / keypoints | Flip only with explicit flip pairs (Ultralytics `flip_idx`, RF-DETR `keypoint_flip_pairs`, MMPose flip indices); rotation and scale; visibility update after crops | AlbumentationsX `label_mapping` if AGPL is acceptable | torchvision/Kornia flips without remapping left/right identities |
| Depth (monocular, stereo) | Flips, crops with matching depth, photometric aug on RGB only | Canonical camera transform for mixed cameras (Metric3D, arXiv 2307.10984) | Resizing metric depth without adjusting intrinsics; flipping one stereo view without swapping |
| Video | One parameter set for all frames (torchvision `Video`, Kornia `VideoSequential`, SAM 2 `consistent_transform`) plus mild per-frame colour noise (SAM 2.1 config) | Temporal crops/speed jitter | Independent per-frame geometric augmentation |
| OCR / documents | Augraphy / docTR degradations, small rotations, perspective, blur, JPEG; aspect-ratio bucketing | Synthetic text rendering | Flips, large rotations, crops through text |
| Medical 2D/3D | nnU-Net v2 as-is (resample to median spacing, CT or z-score normalisation, its augmentation set) (D, B3) | MONAI/TorchIO artefact simulation (bias field, motion, ghosting, low-resolution) | Mirroring when labels are side-specific (use `nnUNetTrainerNoMirroring`); per-image min-max for CT; TTA without validation (arXiv 2604.09697) |
| Pathology (H&E) | Stain colour augmentation (HSV/HED) first (arXiv 1902.06543); patches at fixed MPP; D4 flips/rotations | Macenko/Reinhard normalisation (torchstain) for extra robustness | Vahadane via TIAToolbox with current scikit-learn (unstable warning); patching by pyramid level index |
| Remote sensing / multispectral | Per-band train-split statistics; Sentinel-2 offset for processing baseline >= 04.00; D4; tiling with overlap; checkpoint-specific stats (DINOv3 SAT weights differ from web weights) | TorchGeo spectral indices (before normalisation), SatSlideMix, band dropout | ImageNet RGB stats on non-RGB bands; hue jitter across spectral bands |
| Thermal | Fixed radiometric scaling, geometric aug, noise, blur, contrast/gamma | CLAHE as augmentation | Hue/saturation jitter; per-frame automatic gain normalisation that differs between train and serve |
| Point clouds (reference) | Rotation about the gravity axis, scaling, flips, jitter, grid sampling (Pointcept) | - | Arbitrary 3D rotations for gravity-aligned scenes |
| Degraded inputs (blur, noise, low light, haze, JPEG) | Train on matching degradations (Real-ESRGAN-style second-order pipeline, nnU-Net low-res simulation); evaluate on real degraded data (arXiv 1701.01924, 1808.08750) | A restoration front end only if a held-out test shows a gain, ideally trained with the task loss (arXiv 1706.04284; Sun et al. NeurIPS 2022) | Dehaze/enhance-then-classify by default (arXiv 1810.05716); diffusion SR in front of measurement or medical tasks |
| Robustness targets | AugMix / PixMix / DeepAugment; evaluate on ImageNet-C/-R/-A and, for web-scale models, LAION-C (arXiv 2506.16950) | Class-conditional augmentation for hurt classes (arXiv 2401.01764) | Claiming OOD robustness from ImageNet-C alone for foundation models |
| Synthetic / generative data | Mix synthetic with real, keep real-only val/test; best when real data is scarce or the target is OOD (arXiv 2312.04567) | Copy-paste of real or generated instances (arXiv 2012.07177, 2212.03863); domain randomisation when a simulator exists (arXiv 1804.06516) | Replacing real data with synthetic; letting synthetic images outnumber real ones without a diversity strategy (arXiv 2312.02253) |
| Test-time augmentation | Flip (+ multi-scale for detection with Weighted Boxes Fusion, arXiv 1910.13302) only after a measured validation gain | Learned TTA aggregation (arXiv 2011.11156) | TTA as a default "free" improvement, especially with BatchNorm models on medical data (arXiv 2604.09697) |

**Always check before training:** visualise 50 augmented samples with their boxes/masks/keypoints drawn; confirm the serve-time preprocessing reproduces eval-time pixels; log the exact augmentation config and library versions with the run.

## Could not verify

- **SAM (2023) training augmentation**: the ar5iv and arXiv HTML renderings were truncated before the training-recipe appendix, so whether SAM used large-scale jitter was not confirmed. The SAM 2.1 fine-tuning config in D was read directly.
- **SAM 3 training augmentation and preprocessing**: not reviewed; the Hugging Face weights are gated.
- **DINOv3 checkpoint configs**: the Hugging Face `preprocessor_config.json` files are gated; the normalisation constants come from the DINOv3 README only.
- **TorchIO transform renaming**: the GitHub main branch exports `Affine`, `Motion`, `Ghosting`, ... without the `Random` prefix, but which release introduces this (and whether the old names stay as aliases) was not confirmed; the released docs still show `RandomX` names.
- **AlbumentationsX telemetry contents**: the opt-out variables come from the project docs and a PR summary surfaced by search; what is transmitted was not audited in the source.
- **Whether `ultralytics` or `rfdetr` will switch their optional dependency to `albumentationsx`**: both currently request `albumentations`; future plans were not checked.
- **Evidence for thermal-specific preprocessing** (fixed radiometric scaling vs per-frame AGC): no primary study was verified; the guidance is a practitioner rule.
- **Medical laterality evidence**: no primary study quantifying the harm of mirroring side-specific anatomy was verified; the rule follows from nnU-Net providing `nnUNetTrainerNoMirroring`.
- **2024-2026 augmentation papers** (Sample-aware RandAugment 2508.08004, DiffuseMix 2405.14881, the 2026 medical TTA study 2604.09697, LAION-C 2506.16950): title, date and abstract confirmed through the arXiv API; results beyond the abstracts and code quality were not checked.
- **Sun et al. NeurIPS 2022** (restoration for detection): confirmed via the NeurIPS proceedings page and a search summary; the arXiv ID was not checked.
- **Low-light enhancement for detection**: recent studies found by search report both gains (e.g. enhancement front ends on ExDark) and no gain; no systematic primary benchmark was verified, so treat it as case-by-case.
- **Licences of pretrained restoration weights** (SUPIR, DiffBIR, InvSR, SeedVR2, HAT, NAFNet): only the GitHub repository licence was read, not separate weight or model-card terms.
- **ResNet Strikes Back table values**: read from the ar5iv rendering of arXiv 2110.00476 via a summarising fetch, not from the PDF.
- **Kornia vs Albumentations semantic differences**: taken from RF-DETR's documentation of its Kornia backend, not tested.
- **DEIMv2 relicensing**: the licence change (Apache-2.0 to a custom non-commercial licence, commit `bb64e5e`, 2026-08-24) was read from the repo's commit history and LICENSE files; whether copies obtained before that date keep Apache-2.0 terms is a legal question that was not assessed.
- **`volumentations` on PyPI** (0.1.9, 2025-06-17, MIT): provenance (which repository) was not confirmed, so it is not listed.
